# 星露谷类开放世界游戏——完整开发流程方案

> 项目定位：零基础开发者在 AI 智能体协助下，逐步开发一款融合农场经营、城镇生活、宠物收集、开放区域探索、动作战斗、角色成长、交通、恋爱婚姻和家庭系统的 2D 像素风单机游戏。
>
> 文档版本：v1.0  
> 编制日期：2026-07-21  
> 第一发布平台：Windows PC

---

## 一、项目总体定位

暂定项目代号：**灵境农场**。

游戏类型：

> 2D 俯视角像素风，融合农场经营、城镇生活、宠物收集、开放区域探索、动作战斗和角色成长的单机 RPG。

核心特色：

1. 农场、采集、钓鱼、挖矿和家具布置。
2. 城镇发展、商店升级和 NPC 日常生活。
3. 不通过战斗捕捉宠物，宠物主要服务于生活与探索。
4. 森林、洞穴、遗迹等开放区域探索和环境解谜。
5. 多武器实时战斗、人物技能和魔法能力。
6. 击败怪物获得原创的“灵核/星印”，形成不同成长流派。
7. 交通工具、房屋进出、室内交互、恋爱、结婚和儿童成长。

### 1.1 技术基线

- 游戏引擎：Godot 4 稳定版，项目开始后锁定具体版本。
- 编程语言：GDScript，尽量使用静态类型。
- 游戏画面：2D 俯视角像素风。
- 基础分辨率：`640×360`，使用整数倍缩放。
- 地图网格：统一采用 `32×32`，项目中不混用不同基础网格。
- 地图形式：多个互相连接的开放区域，不制作真正无缝的大世界。
- 第一平台：Windows PC，键盘鼠标优先。
- 版本管理：Git + Git LFS，远程使用私有 GitHub 或 Gitee 仓库。
- 第一阶段不开发：多人联网、手机端、主机端和大型无缝地图。

### 1.2 原创与素材原则

可以参考《星露谷物语》、怪物收集游戏和开放世界游戏的玩法结构，但不直接使用其他商业游戏的角色、名称、剧情、地图、音乐或拆包素材。

测试阶段优先使用：

- CC0 素材；
- 明确允许游戏使用的免费素材；
- AI 生成的临时图片；
- 自制色块和灰盒占位素材；
- 标记为 `PROTOTYPE_ONLY` 的临时资源。

即使是内部测试素材，也必须记录来源，避免后期无法判断哪些资源需要替换。

## 二、核心游戏循环

```text
起床并规划当天活动
→ 种田、制作和经营农场
→ 进入城镇与 NPC 互动
→ 前往森林、矿洞和遗迹探索
→ 采集、战斗、解谜或捕捉宠物
→ 获得材料、金币、经验和星印
→ 升级工具、房屋、装备和能力
→ 解锁交通工具、新区域和新剧情
→ 回家保存并进入下一天
```

游戏需要维持三条都能推进进度的成长路线：

- **生活路线**：农业、钓鱼、烹饪、家具和城镇经营。
- **探索路线**：宠物、解谜、交通工具、收集和隐藏区域。
- **战斗路线**：武器、魔法、怪物、等级、装备和星印。

不能让其中一条路线完全压过其他路线。例如战斗不能成为唯一赚钱方式，宠物能力也不能跳过所有谜题。

## 三、版本范围和功能分期

| 需求 | 首次实现阶段 | 测试版范围 |
|---|---:|---|
| 农场、钓鱼、砍树、挖矿 | M1～M2 | 完整基础循环 |
| 城镇经营 | M5 | 繁荣度和 3 项升级 |
| 家具设计 | M2/M5 | 家具摆放基础版 |
| 非战斗宠物捕捉 | M3 | 5～10 种宠物 |
| 开放世界探索 | M3 起 | 多个开放区域，不做无缝世界 |
| 洞穴、闯关和谜题 | M3～M4 | 10 层洞穴、2～4 个谜题 |
| 武器和怪物战斗 | M1/M4 | 剑、弓、法杖 |
| 魔法和人物能力 | M4 | 3 条技能树 |
| 类似魂环的成长 | M4 | 原创“灵核/星印”系统 |
| 100～150 级 | 完整版 | 测试版只开放 1～20 级 |
| 金色武器 | M4 | 先制作 1 把神话武器 |
| 交通系统 | M3/M5 | 矿车和坐骑 |
| 恋爱结婚 | M5 | 2 名可恋爱 NPC |
| 生育和儿童成长 | 完整版 | 测试版只做到婴儿阶段 |
| 房屋进出与交互 | M1/M2 | 完整基础功能 |

### 3.1 第一个可玩测试版本

第一版应控制在以下范围：

- 1 个农场；
- 1 个小镇；
- 1 片森林；
- 1 座 10 层矿洞；
- 8 种作物；
- 10 种宠物；
- 6 种怪物和 1 个 Boss；
- 剑、弓、法杖 3 种武器；
- 3 条小型技能树；
- 8 名 NPC，其中 2 名可恋爱；
- 1 种矿车交通和 1 种坐骑；
- 钓鱼、家具、商店、任务和基础城镇升级；
- 2～5 小时可玩内容；
- 完整的保存与读取。

### 3.2 暂不进入第一版的功能

- 真正无缝的大型开放世界；
- 完整的 100～150 级内容；
- 数百只宠物；
- 多代儿童成长；
- 大规模自由城市建设；
- 多人联机；
- 程序生成的无限地图；
- PC、手机和主机同时开发。

## 四、智能体开发团队

### 4.1 主开发智能体：制作人兼技术负责人

职责：

- 维护游戏设计总纲和版本范围；
- 把需求拆成可以独立验收的小任务；
- 决定系统接口、数据格式和目录结构；
- 分派程序、内容、素材和测试任务；
- 审查代码和不同系统之间的兼容性；
- 运行测试并生成 Windows 试玩包；
- 每周提供变化清单、已知问题和下一步计划。

### 4.2 系统程序智能体

负责：

- 人物移动、碰撞、镜头和动画；
- 交互、背包、快捷栏和装备；
- 农场、采集、钓鱼和制作；
- 战斗、怪物 AI、技能和等级；
- 宠物捕捉、图鉴、跟随和能力；
- NPC 日程、关系、任务和商店；
- 时间、天气、地图切换；
- 存档、读取和存档版本迁移。

限制：

- 不自行扩大玩法范围；
- 不直接修改其他系统的公共接口；
- 不在无关文件中顺手重构；
- 每个系统必须提供测试场景或可重复测试步骤。

### 4.3 内容策划智能体

负责把玩法创意转换为结构化游戏数据：

- 作物、鱼类、矿物和采集物；
- 怪物属性、生成区域和掉落；
- 宠物习性、捕捉条件和探索能力；
- NPC 背景、日程、好感和恋爱事件；
- 任务、对白、谜题和洞穴关卡；
- 武器、技能、经验曲线和星印体系；
- 城镇繁荣度、商店和经济数值。

### 4.4 素材智能体

负责：

- 根据需求在互联网寻找素材；
- 下载到隔离的素材暂存区；
- 记录作者、来源网页和许可；
- 统一图片尺寸、色板、文件名和透明背景；
- 设置 Godot 导入参数；
- 标记可长期使用或必须替换的素材；
- 检查不同素材包的视觉一致性。

### 4.5 QA 与构建智能体

负责：

- 功能测试、回归测试和存档测试；
- 检查脚本报错、场景断链和资源缺失；
- 记录 Bug 的复现步骤、预期结果和实际结果；
- 检查性能；
- 生成带版本号的 Windows 测试包。

## 五、完整开发流程

### M0：项目准备（1～2 周）

交付内容：

- 安装并锁定 Godot 版本；
- 创建 Godot 工程和 Git 仓库；
- 建立目录、命名规范和数据 ID 规范；
- 设置基础分辨率、像素缩放和键位；
- 创建主菜单和测试地图；
- 建立基础存档框架；
- 建立日志和调试面板；
- 导出第一个 Windows 空白测试包。

完成标准：新电脑拉取项目后，可以按照说明启动工程并导出 EXE。

### M1：基本操作原型（2～4 周）

开发内容：

- 四方向移动和跑步；
- 体力、碰撞和镜头；
- 通用交互系统；
- 房屋进入和地图切换；
- 砍树、挖石头、掉落和拾取；
- 背包和快捷栏；
- 一把剑和一种怪物；
- 生命、受伤、击退和死亡；
- 玩家位置、背包和世界状态存档。

完成标准：

> 玩家可以从家出发，砍树、挖矿、击败怪物、捡起资源并保存游戏。

### M2：农场生活原型（约 4 周）

开发内容：

- 锄地、播种、浇水；
- 作物按天成长和收获；
- 时间、昼夜和睡觉；
- 商店购买和出售；
- 5～8 种作物；
- 房屋升级；
- 家具摆放基础版；
- 简化钓鱼玩法。

完成标准：玩家能够连续游玩 3 个游戏日，种植并卖出第一批作物，读档后农田状态不丢失。

### M3：宠物与开放区域（约 4 周）

开发内容：

- 森林、洞穴和隐藏区域；
- 宠物生成的时间、天气和地点条件；
- 投喂、追踪、互动和解谜式捕捉；
- 宠物图鉴、命名、跟随和亲密度；
- 宠物探索能力；
- 矿车和简单坐骑；
- 两个环境谜题。

宠物不参加战斗，可以提供：

- 寻找矿石；
- 提醒隐藏宝箱；
- 自动拾取附近物品；
- 提高钓鱼成功率；
- 发现秘密通道；
- 帮助照顾作物；
- 作为坐骑。

完成标准：玩家能够不通过战斗收服宠物，并使用宠物能力发现隐藏区域。

### M4：战斗和成长（4～6 周）

开发内容：

- 剑、弓、法杖；
- 普通攻击、蓄力攻击和闪避；
- 魔法、法力和元素状态；
- 5 种普通怪物和 1 个 Boss；
- 1～20 级；
- 3 条小型技能树；
- 装备品质；
- 灵核和星印；
- 1 把金色神话武器。

成长循环：

```text
击败精英怪或 Boss
→ 获得灵核
→ 完成吸收或净化挑战
→ 解锁星印
→ 星印改变技能效果
→ 多枚星印组成不同战斗流派
```

技术结构预留 150 级，但测试版只制作 1～20 级，避免提前制造大量无意义的数值内容。

### M5：NPC、城镇和家庭（4～8 周）

开发内容：

- 6～8 名 NPC；
- NPC 日程、对话和礼物；
- 好感、个人任务和关系事件；
- 2 名可恋爱 NPC；
- 约会、结婚和婚后事件；
- 城镇繁荣度；
- 商店和建筑升级；
- 家庭系统的婴儿阶段。

完整的儿童成长、上学、朋友、性格、职业和成年阶段安排在正式版。

### M6：垂直切片（6～8 周）

整合内容：

- 一个完整季节；
- 农场、小镇、森林和 10 层洞穴；
- 8 种作物、10 种宠物；
- 6 种怪物和 1 个 Boss；
- 3 种武器和 3 条技能树；
- 8 名 NPC 和 2 条恋爱线；
- 基础交通、家具、钓鱼和谜题；
- 2～5 小时可玩流程；
- 新手教程、设置、音频和稳定存档。

完成标准：没有接触过项目的玩家，不看开发说明也能完成第一季主线和 Boss 战。

## 六、第一个月详细任务表

### 第 1 周

- 安装和配置 Godot；
- 建立项目、目录和 Git 仓库；
- 设置键位；
- 完成角色四方向移动、碰撞和镜头；
- 导出第一个 Windows 测试包。

### 第 2 周

- 完成交互检测；
- 添加树木、石头和掉落物；
- 完成砍树、挖矿和拾取；
- 制作背包和快捷栏；
- 保存玩家位置和背包。

### 第 3 周

- 制作土地、种子和作物状态；
- 完成锄地、播种、浇水、成长和收获；
- 添加昼夜推进和睡觉；
- 添加商店买卖；
- 连续测试 3 个游戏日。

### 第 4 周

- 添加一种怪物；
- 添加剑攻击、受伤和死亡；
- 添加一只可投喂捕捉的宠物；
- 连接农场、森林和小屋；
- 发布首个 10～15 分钟内部原型。

第一个月唯一成功标准：

> 玩家能从家出发，种下一颗作物，砍一棵树，击败一只怪物，用食物收服一只宠物，回家保存；重新打开游戏后，所有关键状态仍然存在。

## 八、系统开发依赖顺序

```text
项目启动与输入
→ 玩家移动和碰撞
→ 通用交互
→ 物品数据库和背包
→ 工具、采集和掉落
→ 农业和时间
→ 属性、伤害和状态
→ 战斗和怪物 AI
→ 掉落、经验和技能
→ 宠物捕捉与跟随
→ 世界状态和地图切换
→ NPC、对话、任务和商店
→ 存档与版本迁移
→ UI、教程和内容扩充
```

不能跳过基础依赖直接开发大型系统。例如没有稳定的物品数据库和存档之前，不应批量制作宠物、任务和农作物。

## 九、数据驱动设计

建议建立以下数据资源：

- `ItemDefinition`
- `CropDefinition`
- `ToolDefinition`
- `WeaponDefinition`
- `MonsterDefinition`
- `PetDefinition`
- `SkillDefinition`
- `QuestDefinition`
- `LootTable`
- `NPCDefinition`

稳定 ID 示例：

```text
crop_turnip
weapon_rusty_sword
monster_green_slime
pet_moss_fox
quest_first_harvest
```

显示名称和内部 ID 必须分离，为后续中文、英文等本地化预留空间。新增作物、怪物、宠物时，应主要新增数据资源，而不是复制和修改核心代码。

## 十、存档方案

存档位置：`user://saves/slot_01.json`。

存档应包含：

- `save_version`；
- 创建时间和游戏时间；
- 玩家位置、属性和装备；
- 背包与快捷栏；
- 农田、作物和浇水状态；
- 任务状态；
- 世界物体状态；
- Boss 和宝箱状态；
- NPC 关系状态；
- 已捕捉宠物和图鉴；
- 城镇升级状态。

安全要求：

- 先写入临时文件，再替换正式存档；
- 至少保留一个自动备份；
- 加载失败时禁止覆盖旧存档；
- 存档结构修改时提供版本迁移；
- 不保存运行时实例 ID 或完整场景树。

## 十一、互联网素材获取方案

### 11.1 推荐来源

- [Kenney](https://kenney.nl/assets)：大量 CC0 游戏素材。
- [itch.io 免费游戏素材](https://itch.io/game-assets/free)：像素角色、农场、怪物、地图和 UI。
- [OpenGameArt](https://opengameart.org/)：综合游戏素材，优先筛选 CC0。
- [Game-icons.net](https://game-icons.net/)：物品和技能图标，多数需要署名。
- [Freesound](https://freesound.org/)：环境和动作音效，优先选择 CC0。
- [Free Music Archive](https://freemusicarchive.org/)：音乐，需要逐曲检查许可。
- [Google Fonts](https://fonts.google.com/)：字体，注意保存字体许可。

素材状态统一使用：

- `PROTOTYPE_ONLY`：只用于内部测试；
- `LICENSE_REVIEW`：许可不清，禁止进入公开版本；
- `REPLACE`：正式版之前必须替换；

### 11.5 素材规格

- 地图瓦片：PNG、透明背景、32×32 单元格；
- 角色：32×48 或 32×32，项目内保持一致；
- 动画：至少包含四方向移动；
- 图标：32×32 或 64×64；
- 短音效：WAV，44.1/48 kHz；
- 背景音乐：OGG，支持循环；
- 字体：TTF/OTF，并覆盖所需中文字符；
- 像素图片关闭 Filter 和 Mipmaps，使用 Nearest 缩放；
- 原始素材和处理后的游戏素材分目录保存。

## 十三、测试和完成标准

### 13.1 功能完成标准

任何功能必须同时满足：

- 可以从正常游戏入口使用；
- 不依赖编辑器手动修改；
- 没有阻断性错误；
- 操作具有明确反馈；
- 失败条件有提示；
- 支持保存和读取；
- 不破坏上一版本的核心玩法；
- 数据没有分散硬编码；
- 存在最小测试场景或自动测试；
- 素材已经登记来源；
- QA 可以按照步骤独立复现。

### 13.2 测试类型

- 单元测试：背包堆叠、伤害、经验、作物天数和掉落边界。
- 集成测试：砍树入包、种植到收获、杀怪掉落、捕宠到图鉴。
- 场景测试：所有地图能够加载，出口和入口正确连接。
- 存档测试：新游戏、保存、退出、读取、死亡和跨地图状态。
- 性能测试：存在约 20 个怪物、20 个掉落物和一只跟随宠物时保持稳定。
- 回归测试：新增功能不能破坏以前已经通过的玩法。

### 13.3 Bug 优先级

- P0：无法启动、存档损坏、主要流程完全阻断；
- P1：核心玩法无法使用；
- P2：局部错误，但存在绕行方法；
- P3：文字、视觉或轻微体验问题。

存在 P0 或 P1 时，暂停增加新功能。

## 十四、Git 与发布规则

- `main` 分支始终保持可运行和可导出；
- 每项功能使用独立分支，例如 `feature/farming-planting`；
- 一个文件同一时间只由一个智能体负责；
- 公共接口先确认，再允许不同智能体并行开发；
- 禁止无关格式化和大规模顺手重构；
- 二进制素材使用 Git LFS；
- 每周至少生成一个可运行版本标签；
- 每个里程碑生成独立的 Windows 构建和变化记录；
- 没有测试证据的功能不能合并到主分支。

### 周一：计划

- 用户试玩上周版本；

- 每天至少进行一次集成检查。

- 停止加入新功能；
- 合并通过自测的修改；
- 修复系统连接问题；

## 十六、主要风险和控制措施

### 16.1 范围失控

控制办法：

- 每个里程碑只验证一个核心问题；
- 新想法先进入候选任务池；
- 增加一项新功能时移出同等工作量的旧功能；
- 每四周进行一次删减评审。

### 16.2 智能体生成代码难以维护

控制办法：

- 先确定接口和目录，再编写代码；
- 每个脚本只承担一种主要职责；
- 禁止重复创建相同作用的管理器；
- 每次提交保持小而可审查；
- 拒绝没有测试的大量重写。

### 16.3 存档损坏

控制办法：

- 存档带版本号；
- 临时写入后原子替换；
- 保留自动备份；
- 加载失败时不覆盖旧存档；
- 每个里程碑测试旧存档迁移。

### 16.4 数值膨胀

控制办法：

- 先平衡 1～20 级，再扩展到更高等级；
- 记录金币、经验和材料的获取速度；
- 让生活、探索和战斗都能推进主目标；
- 防止宠物能力跳过全部谜题。

### 16.5 素材风格混乱

控制办法：

- 统一像素尺寸、色板、轮廓和光照方向；
- 素材先进入待处理区；
- 尽量按区域使用统一素材包；
- 每月替换一批最不协调的素材；
- 公开发布前清除所有许可不明素材。

## 十七、预计开发周期

在零基础、AI 辅助、持续投入的情况下：

- 1～2 周：项目骨架；
- 1 个月：10～15 分钟基础原型；
- 3～4 个月：30～60 分钟 MVP；
- 8～12 个月：2～5 小时垂直切片；
- 18～30 个月：内容较完整的抢先体验版；
- 3～5 年：接近完整设想的正式版本。

AI 能明显加快代码、数据、文档和测试工作，但地图、美术统一、剧情内容、数值平衡和实际试玩仍需要持续投入。

## 十八、项目启动顺序

正式开始开发时，按照以下顺序执行：

1. 创建 Godot 项目和 Git 仓库。
2. 建立设计文档、素材台账和测试清单。
3. 完成人物移动、碰撞、镜头和测试地图。
4. 完成交互、采集、背包和存档。
5. 完成农业闭环。
6. 完成一种怪物和基础战斗。
7. 完成一只非战斗宠物的捕捉闭环。
8. 连接农场、小屋和森林。
9. 导出第一个 Windows 测试包。
10. 根据试玩反馈再进入矿洞、钓鱼、NPC 和技能开发。

首个原型验收目标：

> 玩家从小屋出发，种下一颗作物，砍倒一棵树，击败一只怪物，用食物收服一只宠物，回家保存；重新启动游戏后，所有关键状态仍然正确。

只有这个闭环稳定且有趣之后，项目才进入大规模内容扩展。
